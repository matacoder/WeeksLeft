# WeeksLeft

**Обои для Windows с картой прожитых недель — и тех, что ещё впереди.**

Двадцать дизайнов. 4K и любые другие разрешения. Перерисовываются раз в неделю.
В фоне при этом не висит ничего.

### Что это

Приложение считает, сколько недель ты прожил и сколько осталось по таблицам смертности твоей
страны, рендерит из этого картинку и ставит её обоями. Раз в неделю картинка обновляется сама.

Дизайны — обычные HTML-файлы. Рендер идёт через WebView2 (движок Edge, уже стоит во всех
Win10/11), результат сохраняется в PNG нужного разрешения и ставится обоями через COM-интерфейс
`IDesktopWallpaper` — свой файл на каждый монитор, с учётом реального физического разрешения.

### Почему это ничего не ест

Резидентного процесса нет вообще. Вместо него — задача в планировщике Windows
(`WeeksLeftWallpaper`) с триггерами: вход в систему, разблокировка сессии, раз в день.

При запуске приложение сравнивает текущее состояние (номер недели, тема, акцент, шаблон,
раскладка мониторов) с тем, что было применено в прошлый раз. Если ничего не изменилось —
выходит примерно за 30 мс, ничего не рендерив. Если изменилось — поднимает WebView2, рисует
PNG и выходит.

| | |
|---|---|
| В простое | 0 МБ, 0% CPU — процесса нет |
| Проверка «не изменилось» | ~30 мс |
| Полный рендер 4K | ~1.2 с, пик ~150–200 МБ, раз в неделю |
| Размер | 2.2 МБ (нужен .NET 8 Desktop Runtime) |

### Установка

```powershell
dotnet publish src\WeeksLeft\WeeksLeft.csproj -c Release -o dist
dist\WeeksLeft.exe
```

Дальше в окне: дата рождения → страна (определяется сама) → дизайн → «Применить сейчас».
Галочка «Обновлять автоматически» создаёт задачу в планировщике. Права администратора не нужны.

### Ключи командной строки

| Ключ | Что делает |
|---|---|
| *(без ключей)* | окно настроек |
| `--apply` | тихо обновить обои, если что-то изменилось (это запускает планировщик) |
| `--apply --force` | перерисовать принудительно |
| `--dry-run` | отрендерить PNG, но **не** трогать рабочий стол |
| `--install` | установить в систему (копия в `%LOCALAPPDATA%\Programs`, ярлык, задача, запись в «Приложениях») |
| `--uninstall` | удалить; `--quiet` — без диалогов |
| `--install-task` / `--uninstall-task` | только задача в планировщике |
| `--shoot <файл.html> <ш> <в> <out.png>` | отрендерить произвольную страницу — для отладки шаблонов |

Конфиг и логи: `%LOCALAPPDATA%\WeeksLeft\` (`config.json`, `last-run.log`, `out\`).

Приложение собрано как WinExe, поэтому PowerShell не ждёт его завершения и не видит код
возврата. Для скриптов: `Start-Process WeeksLeft.exe -ArgumentList '--apply' -Wait -PassThru`.

### Про статистику

Ожидаемая продолжительность жизни **при рождении** — неправильная метрика для взрослого.
Она включает младенческую и раннюю взрослую смертность, которую ты уже пережил, поэтому
занижает твой реальный ожидаемый финальный возраст.

По умолчанию используется **остаточная ожидаемая продолжительность e(x) в твоём текущем
возрасте**. Полная таблица смертности выводится из e0 страны и пола методом Брасса
(relational logit model, β = 1): подбирается α, при котором таблица воспроизводит нужное e0,
дальше берётся e(x). Всё оффлайн, без сети, ~50 КБ данных в бинарнике.

Разница ощутима: мужчина 38 лет в России — e0 = 68 лет, а ожидаемый финальный возраст ≈ 73.

Доступны три модели: `remaining` (по умолчанию), `birth` (классическая цифра из статистики),
`custom` (свой целевой возраст). Плюс ручной override числа лет.

Данные — приблизительные оценки уровня UN WPP 2024 / WHO GHO, округлённые до 0.1 года,
в `LifeData.cs`. Обновляются правкой одного текстового блока.

### Настройки

**Кто ты** — дата рождения, пол, страна (`GetUserDefaultGeoName`, то есть Home Location
в Windows; без гео и без запросов по IP).

**Дизайн** — галерея из 20 шаблонов с живым превью. По умолчанию дизайн **меняется каждую
неделю**. Клик по карточке ставит этот дизайн сразу, и он держится до конца недели, дальше
ротация продолжается; режим «Фиксированный» оставляет его навсегда. Тема (тёмная / светлая /
как в Windows), акцент (свой или системный акцент Windows), единицы (недели / месяцы / дни /
годы), язык обоев (RU / EN / авто).

Настройки сохраняются сами по мере ввода — закрытие окна ничего не теряет.

**Что показывать** — тон формулировок, числа, предполагаемый год окончания (**выключено по
умолчанию**), своя строка текста, отступ под иконки рабочего стола, отступ под панель задач.

**Тон** — по умолчанию позитивный: «1814 недель **впереди**», а не «осталось». Нейтральный
режим возвращает обратный отсчёт и memento mori.

**Вехи жизни** — свои события с датой, подписью и цветом; отмечаются точками на сетке недель.

**Поведение** — мониторы (одинаково на всех / только основной / свой дизайн на каждый),
частота обновления, автозапуск, архив прошлых обоев.

**Установка в систему** — кнопка копирует приложение в `%LOCALAPPDATA%\Programs\WeeksLeft`,
кладёт ярлык в меню «Пуск», регистрирует задачу в планировщике на установленную копию и
добавляет запись в «Приложения и возможности», откуда его можно снести штатным способом.
Всё в профиле пользователя, права администратора не нужны.

### Двадцать дизайнов

Сетки из кружков и квадратов: `01-grid` (классическая сетка недель), `04-squares`,
`05-heatmap` (прожитые недели теплеют к акценту), `06-fullbleed` (точки во весь экран,
число выжжено в середине), `18-mosaic`, `20-pixel`, `13-blueprint` (будущее — контуры,
как ненарисованная деталь).

Другие масштабы: `07-months` (плитка на месяц), `08-years` (год-квадрат, текущий заполняется
снизу), `17-thisyear` (52 недели этого года крупно), `09-timeline` (лента), `10-bars`.

Формы: `03-rings`, `11-spiral` (недели по спирали с равномерным шагом дуги), `19-orbit`
(годовые кольца, как у дерева), `16-horizon` (солнце идёт по дуге в такт прогрессу).

Типографика: `02-minimal`, `15-typo`, `14-cards`, `12-terminal`.

### Свой дизайн

Положи HTML-файл в `assets/templates/` — он появится в галерее. Минимальный шаблон:

```html
<link rel="stylesheet" href="base.css">
<canvas id="c"></canvas><div id="ui"></div>
<script src="lib.js"></script>
<script>
function render(d) {
  var p = WL.palette(d), T = WL.t(d.lang), b = WL.box(d), c = WL.counts(d);
  var g = WL.canvas(b, p);                       // canvas, already filled with the bg

  var gm = WL.wrapGeom(d, b, { gap: 0.3 });      // picks 52 / 104 / 156 ... columns
  var ox = b.left + (b.w - gm.w) / 2, oy = b.top + (b.h - gm.h) / 2;
  WL.eachWeek(d, gm, ox, oy, function (x, y, i) {
    WL.dot(g, x, y, gm.cell, i.state === 'past' ? p.dim(0.6)
                           : i.state === 'now'  ? p.accent : p.dim(0.12));
  });

  var add = WL.layer();                          // absolutely positioned text layer
  WL.header(add, d, p, b);
  add(WL.fmt(c.left, d.lang) + ' ' + T[c.kLeft], {
    cls: 'big nw', left: b.left + 'px', bottom: b.bottom + 'px',
    fontSize: (90 * b.u) + 'px', color: p.fg
  });
}
WL.boot(render);
</script>
```

Полезное из `lib.js`: `WL.geom` — сетка фиксированной формы (52 недели в строке),
`WL.wrapGeom` — сама подбирает число колонок под пропорции экрана (52 × 75 никогда не
заполнит 16:9), `WL.eachCell` / `WL.eachWeek` — обход ячеек, `WL.dot` / `WL.square` —
метки, `WL.palette` — цвета с проверкой контраста акцента, `WL.counts` — числа с учётом
единиц и тона, `WL.box` — безопасные зоны и масштабный коэффициент `u`.

`WL.boot` сам разбирается, откуда пришли данные (рендерер или превью в настройках) и
сигналит хосту, когда страница готова к съёмке. Вьюпорт равен точному размеру обоев в
пикселях, так что можно считать раскладку прямо в px от `window.innerWidth/innerHeight`
(это и делает `WL.box`, уже с учётом безопасных зон).

Что приходит в `d`: `weeksLived`, `weeksTotal`, `weeksLeft`, `percent`, `daysLived`,
`daysLeft`, `monthsLived`, `monthsTotal`, `ageYears`, `yearsTotal`, `yearsLeft`,
`gridRows`, `gridCols`, `curRow`, `curCol`, `endDate`, `endYear`, `countryName`, `sex`,
`theme`, `accent`, `lang`, `granularity`, `showNumbers`, `showEndDate`, `customText`,
`safeLeftPct`, `safeBottomPct`, `width`, `height`, `milestones[]`.

Название для галереи добавляется в `assets/templates/manifest.json`.
Отладка: `WeeksLeft.exe --shoot assets\templates\мой.html 3840 2160 out.png`.

### Мелочи, которые важны

* Windows по умолчанию пережимает обои в JPEG качества ~85 — на 4K-градиентах это полосы
  и мыло. Приложение выставляет `HKCU\Control Panel\Desktop\JPEGImportQuality = 100`.
* Windows кэширует обои по пути файла, поэтому имя PNG содержит хэш состояния.
* Физическое разрешение монитора берётся из `IDesktopWallpaper.GetMonitorRECT`, а не из
  WinForms: при 125% масштабе `Screen.Bounds` вернёт 3072×1728 вместо настоящих 3840×2160.

* Тёмная тема — **чистый чёрный** `#000000`: на OLED такие пиксели физически выключены.
* Сетка 52 × 75 не заполняет 16:9 — по высоте упирается первой. `WL.wrapGeom` переносит
  недели на строки по 52 / 104 / 156 и берёт раскладку, закрывающую больше кадра.
* Локальный UI в WebView2 нельзя отдавать через виртуальный хост `https://` — это стоило
  1.5 с на запуске против обычного `file://`. Имя вида `*.local` добавляет ещё 400 мс,
  потому что этот TLD уходит в mDNS.

### Что пока не сделано

* Обои экрана блокировки не ставятся (другой API).
* Таблица e0 — приблизительная, не выгружена автоматически из UN WPP.
